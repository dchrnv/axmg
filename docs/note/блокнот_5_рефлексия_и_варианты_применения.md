# axmv2 — Блокнот: Рефлексия, диагноз упрощений, MCP-архитектура и проработка Ядра

**Дата:** 2026-08-14  
**Статус:** Сессия рефлексии после реализации III септенера. Переход от жесткого конвейера эвристик к архитектуре **«Универсальное Ядро памяти + MCP + Локальная LLM / OpenClaw»**.

---

## 1. Диагноз: Где и почему произошёл сбой/чрезмерное упрощение

### 1.1. Разрыв между фундаментальной математикой (I–II) и эвристиками (III)
* **Септенеры I и II (Полка, Колесо, Смерть, PPMI, Surprise):**
  Были выстроены строго снизу вверх на законах теории информации и Merkle-структур. Любой шаг подтверждался held-out проверками и «дверью на числе». Это был честный поиск устойчивых единиц из потока байт.
* **Септенер III (Порт → Модератор → Дьявол → Башня → Оценщик → Суд → Мир):**
  Произошла попытка замаппить архетипическую метафору (воронку принятия решений) в код «в лоб». Вместо эмерджентного мышления получился каскад жестких статических фильтров (отсечение частот, удаление тривиальных пар, выбор Top-3 по контрасту). Это не принятие решений агентом, а эвристический отбор n-грамм.

### 1.2. Отсутствие предиктивного кольца (Active Inference / Predictive Coding)
* Настоящая агентность и познание строятся вокруг **предсказания следующего состояния** и минимизации ошибки предсказания (Surprise).
* В текущем ядре `surprise.rs` вычисляет сжатие и словарный прирост статически («после факта»). Нет контура генерации: модель не выдвигает гипотез о будущем входе и не корректирует свое состояние по ошибке прогноза.

### 1.3. Ловушка жестких N-грамм (отсутствие узоров с переменными)
* Карточка токена знает только жесткое сцепление: $A + B \to C$.
* Модель не умеет выделять продуктивные схемы с «дырками» (слотами вида $A + [?] + B$), которые были отложены в `DEFERRED.md`. Из-за этого обобщение ограничено буквальными совпадениями подстрок.

## 2. Три прикладных варианта над единым субстратом

1. **Вариант А: Автономный адаптивный токенизатор** — потоковое сжатие и кодирование произвольных бинарных потоков (IoT, геномика, сетевые протоколы).
2. **Вариант Б: Детектор аномалий и нулевых дней** — мониторинг телеметрии и логов в реальном времени через онлайн-всплеск метрики `Surprise`.
3. **Вариант В: Честная когнитивная архитектура** — замкнутый предиктивный цикл с узорами и моторным контуром.

---

## 3. Целевой синтез: Ядро памяти + Локальная LLM + OpenClaw + MCP

Истинное продуктовое и архитектурное призвание `axmg` — стать **локальным, прозрачным и детерминированным движком памяти** для локальных нейросетей (Ollama, vLLM, llama.cpp) в связке с агентными средами (OpenClaw).

> *«Говорилка чужая — память своя. Не ширма с проектором, а честный локальный append-only стор».*

```
       ┌─────────────────────────────────────────────────────────────┐
       │             OpenClaw / Агентный хост (MCP-клиент)           │
       │                   + Локальная/Внешняя LLM                   │
       └──────────────┬───────────────────────────────▲──────────────┘
                      │                               │
           [MCP JSON-RPC / stdio]          [MCP JSON-RPC / stdio]
                      │                               │
                      ▼                               ▼
       ┌──────────────────────────────┐ ┌──────────────────────────────┐
       │     1. axmg-memory-mcp       │ │    2. axmg-sensory-mcp       │
       │    (СЕРВЕР ПАМЯТИ И ФОКУСА)  │ │   (ВХОДНОЙ ПОТОК СОБЫТИЙ)    │
       │ • Resource: memory://focused │ │ • Слушает логи, Git, датчики │
       │ • Resource: memory://stats   │ │ • Стримит сырые байты        │
       │ • Tool: remember(text)       │ │   в Колесо (Wheel)           │
       │ • Tool: recall(query)        │ │                              │
       │ • Tool: check_surprise(text) │ │                              │
       └──────────────┬───────────────┘ └──────────────┬───────────────┘
                      │                                │
                      └────────────────┬───────────────┘
                                       │
                                       ▼
                      ┌─────────────────────────────────┐
                      │    axmg Core (Rust / Merkle)    │
                      │  Store + Wheel + Death + PPMI   │
                      └─────────────────────────────────┘
```

### Разделение ролей:
* **LLM:** отвечает за рассуждения, человеческий язык, генерацию текста и планирование.
* **OpenClaw:** управляет агентным циклом, маршрутизацией запросов и вызовом внешних инструментов.
* **axmg Core (через MCP):** обеспечивает долгосрочную память, живой сфокусированный контекст, автоматическое забывание шума (Death) и оценку новизны (Surprise).

## 4. Что необходимо фундаментально проработать в Ядре (`axmg-kernel`)

Чтобы стать надежным, высокопроизводительным и математически строгим движком памяти, ядро требует глубокой инженерной ревизии:

### 4.1. Потоковое распознавание и онлайновая нормализация (Online Streaming)
* **Проблема сейчас:** `merge::run` оптимизирован под пакетную обработку целых корпусов/поколений.
* **Что нужно:** Создать интерфейс потокового распознавателя (`StreamingRecognizer`), который принимает чанки байт произвольного размера, выполняет жадную/поколенческую свёртку на лету и инкрементально обновляет счётчики в SoA-арене.

### 4.2. Механизм ассоциативного вспоминания (`recall`)
* **Проблема сейчас:** Ядро умеет идти вниз по составу токена (`bytes_of`), но извлечение связанного контекста вокруг произвольного запроса не оформлено в единую операцию.
* **Что нужно:** Реализовать операцию субграфного поиска:
  $$\text{Query (байты)} \xrightarrow{\text{свёртка}} \text{Токены запроса} \xrightarrow{\text{PPMI-граф}} \text{Ассоциативные соседи} \xrightarrow{\text{декодирование}} \text{Релевантный контекст}.$$

### 4.3. `Surprise` как первоклассный сигнал реального времени
* **Проблема сейчас:** Метрика `surprise.rs` жила как оффлайн-эксперимент (`examples/surprise_experiment.rs`).
* **Что нужно:** Встроить расчет $S_{\text{static}}$ и $S_{\text{growth}}$ прямо в цикл приема данных. Возвращать `surprise_score` синхронно на каждый входящий `remember()` вызов.

### 4.4. Стабильный жизненный цикл фокуса и памяти без блокировок
* **Проблема сейчас:** Запись в redb и пересчет среза Смерти (`death.rs`) на каждый оборот могут вызывать задержки при конкурентном чтении.
* **Что нужно:** Реализовать неблокирующий доступ (Read-Copy-Update или lock-free снапшоты) к активному множеству токенов (`FocusSet`), чтобы MCP-ресурсы вроде `memory://focused` отвечали за доли миллисекунды.

### 4.5. Архитектурная очистка Ядра от статических эвристик
* Вынести или депрекейтнуть жестко зашитые модули III септенера (`devil.rs`, `tower.rs`, `evaluator.rs`, `decision.rs`), перенаправив фокус на стабильные инварианты: **Store + Merge + Wheel + Death + PPMI + Surprise + Clean Facade**.
