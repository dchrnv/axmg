# axmg (Axiom Gemini) — Universal Merkle Memory Engine

[![CI](https://github.com/dchrnv/axmg/actions/workflows/ci.yml/badge.svg)](https://github.com/dchrnv/axmg/actions/workflows/ci.yml)
[![License: AGPL v3](https://img.shields.io/badge/License-AGPL_v3-blue.svg)](LICENSE)
[![Release](https://img.shields.io/badge/release-v0.1.0--core-green.svg)](https://github.com/dchrnv/axmg/releases)

> **«Говорилка чужая — память своя. Не ширма с проектором, а честный локальный append-only стор».**

`axmg` — это легковесный, автономный и математически строгий движок ассоциативной памяти и обнаружения структуры, написанный на Rust. Система преобразует непрерывные потоки байт (текст диалогов, логи, код, телеметрию датчиков) в детерминированный **Merkle DAG** повторяющихся композиций, динамически удерживает живой контекст через забывание шума и предоставляет интерфейсы памяти через **Model Context Protocol (MCP)** для локальных LLM (Ollama, llama.cpp, vLLM) и агентных сред (OpenClaw).

---

## 🏛️ Ключевые архитектурные принципы

1. **Никакого зашитого знания о языке (Чистый байтовый поток):**
   Система не использует словари, грамматики, морфологию или эмбеддинги. Байт — это просто байт. Уровень 0 — 256 фабричных карточек. Все составные структуры (слова, фразы, паттерны) вырастают исключительно из частоты соседства.
2. **Merkle DAG и детерминированная адресация:**
   Идентификатор карточки (токена) — это хеш её состава:
   $$\text{id} = \text{hash}(\text{level}, \text{hash}(\text{child}_1), \text{hash}(\text{child}_2), \dots)$$
   Тело неизменно (append-only), дедупликация гарантирована структурой.
3. **Эпохи времени и вытеснение шума (Epochs & Memory Eviction):**
   Память не пухнет бесконечно. Время дискретизировано на эпохи/такты (`Epoch / Revolution`). Механизм вытеснения (`Eviction / Pruning`) регулярно отсекает отмерший шум (срез пограничных токенов по накопленному PPMI-весу), сохраняя в оперативном фокусе ($K=3$) только актуальные концепты.
4. **Метрика удивления (Surprise) как фильтр внимания:**
   Степень новизны входящих данных численно измеряется через $S_{\text{static}}$ (эффективность сжатия) и $S_{\text{growth}}$ (прирост словаря). Резкий скачок Surprise сигнализирует о важном событии, требующем фиксации.

## 📂 Структура репозитория

- [**`shelf/`**](shelf/) — ядро (`axmg-kernel` на Rust):
  - `store.rs` — Merkle DAG, плоская SoA-арена токенов, intern/lookup.
  - `recognizer.rs` — потоковый $O(N)$ shift-reduce распознаватель `StreamingRecognizer`.
  - `recall.rs` — ассоциативное вспоминание (субграфный PPMI-обход).
  - `wheel.rs` / `death.rs` — такт времени (эпохи), lock-free RCU `FocusSet`, алгоритм вытеснения устаревшей памяти.
  - `ppmi.rs` / `cooc.rs` — матрицы со-встречаемости и PPMI-ассоциации.
  - `surprise.rs` — расчет статического сжатия и словарного прироста.
  - `persist.rs` — транзакционная персистентность на базе `redb` (append-only).
- [**`mcp/`**](mcp/) — серверы Model Context Protocol:
  - `src/main.rs` (`axmg-mcp`) — сервер памяти: ресурсы `memory://focused`, `memory://stats`, `memory://timeline` и инструменты `remember`, `recall`, `check_surprise`.
  - `src/sensory_main.rs` (`axmg-sensory-mcp`) — сенсорный сервер: сборщик логов терминала, git-событий, файловых изменений и сырых байтовых потоков (`--raw`).
- [**`harness/`**](harness/) — тестовая и рантайм-обвязка.
- [**`docs/`**](docs/) — спецификации, заметки и блокноты рефлексии:
  - `note/блокнот_5_рефлексия_и_варианты_применения.md` — концепция ядра, MCP и рефлексия.
  - `spec/СПЕЦИФИКАЦИЯ_ЯДРО_И_MCP.md` — формальная техническая спецификация.

## 🚀 Быстрый старт

### Сборка проекта
```bash
cargo build --release
```

### Запуск серверов памяти
- **Сервер памяти (Memory MCP):**
  ```bash
  cargo run -p mcp --bin axmg-mcp
  ```
- **Сенсорный сервер (Sensory MCP):**
  ```bash
  cargo run -p mcp --bin axmg-sensory-mcp
  ```
- **Прямой байтовый пайплайн (Raw streaming):**
  ```bash
  cat /dev/urandom | head -c 10000 | cargo run -p mcp --bin axmg-sensory-mcp -- --raw
  ```

### Тестирование и валидация
```bash
# Модульные тесты Rust (118 тестов)
cargo test --workspace

# Валидация Ядра и Памяти (Фазы 1 и 2)
python3 verify_phase1.py

# Валидация Сенсорного стримера (Фаза 3)
python3 verify_sensory.py

# Сквозная валидация памяти и сжатия контекста LLM (Фаза 4)
python3 verify_phase4_e2e.py
```

## 📜 Инварианты разработки

Проект строго следует правилам [**`DEV_GUIDE.md`**](DEV_GUIDE.md) и [**`INVARIANTS.md`**](INVARIANTS.md):
- **Дверь на числе:** все критерии и пороги фиксируются *до* прогона;
- **Append-only память:** тело токена неизменно после рождения;
- **Никакой скрытой семантики:** память хранит только топологию графа и частоты.
