## 1. ТОКЕН

Неизменное тело, три поля:

```python
# токен = (level, children); id вычисляется, не хранится
id       = blake2b(level.to_bytes(...) + b"".join(child_ids))  # или иной стабильный hash состава
level    # int: номер уровня
children # tuple[id, ...]: упорядоченный, переменной длины, ссылки на токены уровня ниже
```

Инварианты:
- **id — производное от состава.** Один состав = один id навсегда. Одинаковые дети + уровень → это ОДИН токен (дедупликация по построению).
- Тело токена после создания не изменяется никогда. Никаких update/delete в API — только «добавить» и «прочитать».
- Токен НЕ хранит: родителей, счётчик, текст, флаги, метаданные. Счётчики и родители живут в отдельных восстановимых структурах (раздел 2).
- Уровень 0 — фабричный: все 256 байтов созданы при инициализации, до чтения корпуса. Другие фабричные уровни не создаются.
- Текстовое представление токена (для снапшота) не хранится — вычисляется спуском по children до байтов.

## 2. СТОР

Структуры прототипа (в памяти):

```python
tokens    # dict: id -> (level, children)      — неизменная история
counts    # Counter: id -> число встреч         — живая статистика, ОТДЕЛЬНО от тел
birth_log # list[id]                            — порядок первого появления (хронология)
```

Инварианты:
- Стор = неизменная история (tokens, birth_log) + восстановимые виды (counts и любые временные индексы). Любая структура, невосстановимая пересчётом из tokens+birth_log+корпуса, запрещена.
- Обратный индекс (id → родители), если нужен нормализации, строится ВРЕМЕННО внутри прогона и не сохраняется.
- Персистентность: в конце прогона допускается сериализация в файл (json/pickle) целиком. БД, sled, sqlite — запрещены (этап 1 живёт в памяти).

API стора (исчерпывающий список):
```python
init_factory()            # создать 256 байтовых токенов уровня 0
intern(level, children)   # вернуть id; если состава не было — создать токен, записать в birth_log
touch(id)                 # counts[id] += 1
get(id)                   # -> (level, children)
render(id)                # -> bytes: спуск до уровня 0 (только для снапшота)
snapshot()                # -> dict для JSON (раздел 4)
```
Других функций у стора нет.

## 3. БИБЛИОТЕКАРЬ (нормализация)

Задача: найти в потоке токенов уровня N устойчиво повторяющиеся смежные группы и создать для них токены уровня N+1. Никакого знания о том, ЧТО эти группы означают.

Алгоритм прогона (одна итерация, в духе BPE):

```
вход: последовательность id токенов уровня N (изначально — корпус как байты уровня 0)

1. Подсчитать частоты всех СМЕЖНЫХ ПАР (id_a, id_b) в последовательности.
2. Отобрать пары с частотой >= T (порог рождения; параметр, стартово T=2).
3. Для каждой отобранной пары, начиная с самой частой:
     создать токен уровня N+1: intern(N+1, (id_a, id_b))
     заменить в последовательности все непересекающиеся вхождения пары на новый id.
4. Повторять 1–3, пока итерация рождает хотя бы один новый токен
   (или до K итераций; K — предохранитель, стартово K=200).
выход: свёрнутая последовательность + пополненный стор
```

Уточнения (это решения, не менять молча):
- Пары, только пары. Тройки/группы получаются каскадом: ((a,b),c). Отдельный поиск групп длиннее 2 не реализуется.
- При замене пересекающихся вхождений (aaa при паре aa) — жадно слева направо.
- «Уровень» токена-пары = max(level детей) + 1. Дети могут быть разных уровней — это допустимо и ожидаемо.
- touch() вызывается при каждой встрече токена в потоке, включая замены.
- Порог T и предохранитель K — единственные два параметра всей системы. Третий параметр не появляется.

  ],

Поле `text` — из render(), только здесь. Плюс простая HTML-страница (или markdown-таблица), читающая этот JSON — чтобы человек смотрел глазами. Ничего интерактивного.

## 5. ВХОД

- Корпус: один plain-text файл (UTF-8), читается как БАЙТЫ. Не как символы, не как строки — как поток байтов. Никакого декодирования юникода перед стором: многобайтовая кириллица — это тест, а не проблема (нормализация должна сама собрать байты в устойчивые пары = символы; это первый бесплатный экзамен).
- Контрольный корпус: второй файл другого автора, прогоняется тем же кодом отдельным запуском.
- Предобработка запрещена. Никакой чистки, lowercase, удаления пунктуации.

## 6. ШАГИ РАБОТЫ (гейты)

- **Шаг 1.** Фабрика + чтение корпуса байтами + touch + снапшот частот байтов. СТОП, показать.
- **Шаг 2.** Библиотекарь: одна итерация (только пары уровня 0→1). Снапшот. СТОП: человек смотрит, собрались ли многобайтовые символы кириллицы. Это гейт: если на этом шаге мусор — дальше не идём, разбираемся.
- **Шаг 3.** Полный каскад итераций до остановки. Снапшот. СТОП.
- **Шаг 4.** Прогон контрольного корпуса. Два снапшота рядом. СТОП.
- Оценка результата по критерию — ТОЛЬКО человеком, по числу, зафиксированному до запуска. Ассистент не объявляет успех.
