# Руководство по серверам MCP axmg

Экосистема **axmg** предоставляет стек Model Context Protocol (MCP) серверов для локальных LLM (Ollama, llama.cpp, vLLM, Claude Desktop) и автономных агентных сред (OpenClaw):

1. **`axmg-memory-mcp`** — сервер долговременной ассоциативной памяти на базе детерминированного Merkle DAG, онлайн-метрики удивления (Surprise) и lock-free фокуса внимания.
2. **`axmg-sensory-mcp`** — фоновый сенсорный стример событий среды (терминальные логи, git-коммиты, диффы, изменения файлов и сырые байтовые потоки).

---

## 1. Быстрый старт

### 1.1. Сборка бинарников

```bash
cargo build --release
```

Бинарники будут скомпилированы в:
- `target/release/axmg-mcp` (сервер памяти)
- `target/release/axmg-sensory-mcp` (сенсорный стример)

### 1.2. Подключение к Claude Desktop или OpenClaw

Добавьте конфигурацию серверов в `~/.claude_desktop_config.json` (или `openclaw.json`):

```json
{
  "mcpServers": {
    "axmg-memory": {
      "command": "/home/assis/axmg/target/release/axmg-mcp",
      "args": []
    },
    "axmg-sensory": {
      "command": "/home/assis/axmg/target/release/axmg-sensory-mcp",
      "args": []
    }
  }
}
```

## 2. Сервер памяти `axmg-memory-mcp`

### 2.1. Инструменты (Tools)

#### 1. `remember` — Записать событие в память
Подает текст в Колесо памяти, производит потоковое распознавание через $O(N)$ `StreamingRecognizer`, обновляет активный фокус и возвращает метрику новизны (Surprise).

* **Параметры:**
  - `text` *(строка, обязательный)*: Текст события, факт, код, мысль или результат работы инструмента.
  - `context_tag` *(строка, опционально, по умолчанию `"general"`)*: Семантическая метка (например, `"user_prompt"`, `"tool_output"`, `"error_log"`).

* **Пример вызова:**
  ```json
  {
    "name": "remember",
    "arguments": {
      "text": "В Rust механизм ownership гарантирует безопасность памяти без сборщика мусора.",
      "context_tag": "architecture_insight"
    }
  }
  ```

* **Пример ответа:**
  ```json
  {
    "status": "STORED",
    "revolution": 43,
    "surprise_static": 1.25,
    "surprise_growth": 0.45,
    "verdict": "NOVEL_GROWTH",
    "relevance_score": 1.70
  }
  ```

#### 2. `recall` — Ассоциативное вспоминание
Выполняет субграфный поиск в Merkle DAG через матрицы со-встречаемости (PPMI), ранжирует связанные концепты и декодирует их в связный текстовый контекст.

* **Параметры:**
  - `query` *(строка, обязательный)*: Поисковый запрос или фрагмент мысли.
  - `limit` *(целое число, опционально, 1..=50, по умолчанию `5`)*: Количество ассоциаций.
  - `frequency_floor` *(целое число, опционально, по умолчанию `1`)*: Порог минимальной частоты со-встречаемости.
  - `ppmi_threshold` *(число с плавающей точкой, опционально, по умолчанию `0.0`)*: Порог PPMI-связности.

* **Пример ответа:**
  ```json
  {
    "query": "безопасность памяти",
    "associations": [
      {
        "text": "ownership borrow checker lifetime",
        "relevance_score": 2.45
      },
      {
        "text": "redb транзакционная персистентность",
        "relevance_score": 1.80
      }
    ]
  }
  ```

#### 3. `check_surprise` — Оценка новизны гипотезы
Оценивает степень согласованности входящего утверждения с накопленным опытом **без мутации стора** (гипотетическое сжатие).

* **Параметры:**
  - `hypothesis` (или `candidate_text`) *(строка, обязательный)*: Текст гипотезы.

* **Пример ответа:**
  ```json
  {
    "hypothesis": "Rust компилируется через LLVM в бинарный код",
    "verdict": "FAMILIAR",
    "surprise_static": 0.28,
    "compression_ratio": 2.14
  }
  ```

* **Интерпретация вердиктов:**
  - `FAMILIAR` ($S < 1.0$): Знакомый, предсказуемый паттерн.
  - `INTERESTING` ($1.0 \le S < 1.5$): Частично известная структура в новой комбинации.
  - `SURPRISING` ($S \ge 1.5$): Высокая новизна или неожиданность.

### 2.2. Ресурсы (Resources)

#### 1. `memory://focused`
Текущий снимок активных концептов оперативного фокуса ($K=3$ такта, lock-free RCU-снапшот).
```json
{
  "revolution": 43,
  "focus_count": 331,
  "active_tokens": [
    { "token_id": 14205, "level": 2, "ppmi_weight": 14.85 },
    { "token_id": 8923, "level": 3, "ppmi_weight": 12.42 }
  ]
}
```

#### 2. `memory://stats`
Глобальная статистика хранилища: общее число Merkle-токенов, эпоха (revolution), фактор сжатия и размер активного фокуса.
```json
{
  "total_tokens": 408,
  "current_revolution": 43,
  "compression_ratio": 3.85,
  "active_focus_ratio": 0.811,
  "sequence_length": 1520
}
```

#### 3. `memory://timeline`
Хронологический срез недавних событий памяти со служебными метками и значениями Surprise.
```json
{
  "total_events": 12,
  "recent_events": [
    {
      "id": 12,
      "revolution": 43,
      "context_tag": "architecture_insight",
      "text_preview": "В Rust механизм ownership гарантирует безопасность памяти...",
      "surprise_static": 1.25
    }
  ]
}
```

## 3. Сенсорный сервер `axmg-sensory-mcp`

Сервер `axmg-sensory-mcp` работает как независимый фоновый коллектор, собирающий реальные события среды разработчика/агента и непрерывно подающий их в Колесо памяти.

### 3.1. Сенсорные сборщики
- **Терминальные логи:** захват вывода команд с автоматическим удалением ANSI escape-кодов.
- **Git-события:** фиксация истории коммитов, статуса рабочей директории и unified diffs.
- **Файловый монитор:** отслеживание модификаций исходного кода с защитой от переполнения (порог 64 КБ на файл).
- **Сырые байты:** потоковый адаптер телеметрии.

### 3.2. Ресурсы сенсора
- **`sensory://stats`** — статистика собранных событий:
  ```json
  {
    "total_events": 85,
    "total_bytes_ingested": 142580,
    "collectors_active": 4
  }
  ```
- **`sensory://recent`** — последние входящие сигналы (до 20 событий) с метками источника (`git`, `terminal`, `file`, `raw_bytes`).

### 3.3. Инструменты сенсора
- **`ingest_raw_bytes`** — запись сырых данных в Колесо:
  ```json
  {
    "name": "ingest_raw_bytes",
    "arguments": {
      "data": "526564625f5472616e73616374696f6e",
      "encoding": "hex",
      "source_tag": "hardware_bus"
    }
  }
  ```
  Поддерживаемые кодировки `encoding`: `"auto"`, `"hex"`, `"base64"`, `"utf8"`.

### 3.4. Прямой CLI-пайплайн без JSON
Сенсорный сервер поддерживает потоковую передачу данных напрямую через unix pipe:
```bash
cat /var/log/syslog | cargo run -p mcp --bin axmg-sensory-mcp -- --raw
```

## 4. Архитектурные гарантии и инварианты

1. **Строгая потоковая линейность $O(N)$:** `StreamingRecognizer` гарантирует одинаковое поведение независимо от размера чанков (1 байт или 64 КБ).
2. **ACID Персистентность на redb:**
   - Хранилище `axmg_store.redb` сохраняет дедуплицированные Merkle-токены.
   - Журнал `axmg_timeline.jsonl` обеспечивает непрерывное воспроизведение последовательности.
   - При холодном старте память восстанавливается мгновенно и без потерь.
3. **Lock-Free RCU Фокус:** Чтение ресурсов `memory://focused` и `memory://stats` выполняется без блокировок входящего потока записи через атомарные снапшоты.
4. **Вытеснение шума (Death Pruning):** Вытеснение устаревших токенов по PPMI-весу отсекает шум каждые $K=3$ такта, сохраняя в оперативном фокусе только продуктивные паттерны.

## 5. Эффект для локальных LLM (Экономия контекста 96.89%)

В длинных автономных сессиях агента (OpenClaw, Claude Code):
- **Без axmg (Naive Context Stuffing):** Сырой диалог и логи забивают контекстное окно LLM (тысячи токенов), приводя к деградации рассуждений и высокой задержке.
- **С axmg:** Перед генерацией модель запрашивает `recall(тема)` или читает `memory://focused`.
  - Затраты токенов снижаются с **2769 токенов до 86 токенов** (**32.2x компрессия** контекста).
  - Модель мгновенно получает доступ к ключевым терминам и фактам из прошлых сессий.
