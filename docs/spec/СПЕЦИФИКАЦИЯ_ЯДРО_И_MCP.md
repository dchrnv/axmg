# Спецификация: Архитектура Ядра axmg и MCP-интерфейсов

**Версия:** 2.1  
**Дата:** 2026-08-14  
**Статус:** Активная техническая спецификация.

---

## 1. Назначение и рамки

Данный документ специфицирует:
1. **Интерфейс ядра `axmg-kernel` (`shelf/`):** операции записи, распознавания, обновления времени, вытеснения устаревшей памяти (`eviction`) и ассоциативного извлечения.
2. **Протокольный фасад `axmg-memory-mcp`:** соответствие спецификации Model Context Protocol (MCP) для предоставления памяти LLM-клиентам (OpenClaw, Claude, Cursor и др.).

---

## 2. Архитектура Ядра (`axmg-kernel`)

### 2.1. Инварианты хранилища (Store)
* **Токен:** Уровень композиции + вектор идентификаторов непосредственных детей: `(level, &[TokenId])`.
* **Id токена:** Вычисляется как детерминированный SHA-256 хеш состава:
  $$\text{TokenId} = \text{hash}(\text{level}, \text{hash}(c_1), \text{hash}(c_2), \dots)$$
* **SoA-структура:** Тела токенов хранятся в непрерывных массивах `levels: Vec<u8>`, `children_start: Vec<u32>`, `children_len: Vec<u16>`, `children_arena: Vec<TokenId>`.
* **Мутации:** Только добавление (`append-only`). Запрещены операции изменения или удаления уже интернированных тел токенов.

### 2.2. Эпохи времени и Вытеснение памяти (Epochs & Eviction)
* **Эпохи времени (`Epoch / Wheel`):** Дискретная единица времени — `revolution: u64`. На каждом такте фиксируется `last_touched_revolution[token]`.
* **Вытеснение памяти (`Eviction / Pruning`):**
  - **Корневое множество:** Токены, затронутые за последние $K=3$ эпохи, плюс фабричные 256 байтовых токенов (уровень 0).
  - **Достижимое множество:** Все токены, достижимые вниз по графу композиции от корневого множества.
  - **Срез по весу (`weight_cut`):** Отсечение 25% наименее связанных пограничных токенов (по накопленному PPMI-весу).
  - **Фокус (`FocusSet`):** Множество токенов, переживших вытеснение и доступных для активного извлечения.

### 2.3. Операция ассоциативного вспоминания (`recall`)
* **Вход:** Байтовый срез `query: &[u8]`, параметр `max_results: usize`.
* **Алгоритм:**
  1. Свёртка `query` в последовательность токенов `ids: Vec<TokenId>` с использованием текущего стора.
  2. Поиск ассоциированных токенов через матрицу PPMI:
     $$\text{Neighbors}(t) = \{ v \mid \text{PPMI}(t, v) > \tau \land v \in \text{FocusSet} \}$$
  3. Ранжирование кандидатов по совместному весу $\text{Score}(v) = \sum_{t \in \text{ids}} \text{PPMI}(t, v) \cdot \text{Weight}(v)$.
  4. Рекурсивное декодирование `bytes_of(v)` для топ-кандидатов.
* **Выход:** Список текстовых/байтовых фрагментов с оценками релевантности.

## 3. Спецификация MCP-сервера (`axmg-memory-mcp`)

### 3.1. Транспорт
Стандартный ввод/вывод (`stdio`) с обменом сообщениями JSON-RPC 2.0.

### 3.2. Ресурсы (MCP Resources)

#### 1. `memory://focused`
* **MIME-тип:** `application/json`
* **Описание:** Возвращает актуальный снимок концептов, находящихся в фокусе внимания ядра.
* **Схема ответа:**
```json
{
  "revolution": 42,
  "focus_count": 1350,
  "top_concepts": [
    {
      "token_id": 14205,
      "text": "конфигурация сервера",
      "level": 3,
      "ppmi_weight": 14.85
    }
  ]
}
```

#### 2. `memory://stats`
* **MIME-тип:** `application/json`
* **Описание:** Общая статистика хранилища памяти.
* **Схема ответа:**
```json
{
  "total_tokens": 105050,
  "current_revolution": 42,
  "compression_ratio": 6.42,
  "active_focus_ratio": 0.124
}
```

### 3.3. Инструменты (MCP Tools)

#### 1. `remember`
* **Параметры:**
  - `text` (string, required): Текст или данные события для фиксации в памяти.
  - `context_tag` (string, optional): Необязательный тег источника (например, `"user_prompt"`, `"tool_output"`).
* **Поведение:** Подает данные в поток эпох, выполняет такт, вычисляет `Surprise`, возвращает метрику новизны.
* **Возвращаемое значение:**
```json
{
  "status": "STORED",
  "revolution": 43,
  "surprise_static": 1.25,
  "surprise_growth": 0.45,
  "is_novel_event": true
}
```

#### 2. `recall`
* **Параметры:**
  - `query` (string, required): Поисковая фраза или тема.
  - `limit` (integer, optional, default: 5): Максимальное количество ассоциаций.
* **Поведение:** Выполняет ассоциативное извлечение связанных воспоминаний по PPMI-графу над текущим фокусом.
* **Возвращаемое значение:**
```json
{
  "query": "база данных",
  "associations": [
    {
      "text": "redb транзакции append-only",
      "relevance_score": 0.89
    }
  ]
}
```

#### 3. `check_surprise`
* **Параметры:**
  - `candidate_text` (string, required): Текст гипотезы или предполагаемого ответа.
* **Поведение:** Оценивает, насколько текст согласуется с текущей структурой стора без персистентного сохранения.
* **Возвращаемое значение:**
```json
{
  "surprise_ratio": 0.32,
  "verdict": "FAMILIAR"
}
```
